# ethos_foundation_llm

Two threads sharing one repo:

1. Small-scale reproduction of Steinberg et al. 2021 (CLMBR) on a real Ethos OMOP sample, plus exploration of the MEDS ecosystem tooling (`femr`, `hf_ehr`, `meds-etl`, `meds_reader`).
2. `repr_learn_*` — 5-day pattern-discovery courses (extract → cluster → sequence-mine → embed → rule) applied to specific Ethos cohorts (chest-pain triage, letrozole).

## What's here

### Notebooks (`nb/`)

| Path | What it is |
|---|---|
| `nb/repr_clmbr/clmbr_paper_reproduction.ipynb` | **CLMBR repro.** Pulls a small real patient sample from Snowflake (`ETHOS_PRODUCTION.OMOP_54`), converts OMOP → MEDS → `meds_reader` extract, builds a small vocab, and trains a tiny CLMBR-style model (EmbeddingBag → GRU → next-day-code prediction). |
| `nb/repr_clmbr/meds_tutorial.ipynb` | Small exploratory notebook using **synthetic** MEDS sample data (`meds_testing_helpers`) — no Snowflake needed. Good for understanding the MEDS parquet layout before touching real data. |
| `nb/repr_learn_chestpain/` | 5-day pattern-discovery course on the `dx_9487` (atypical chest pain) cohort — testing whether comorbid Dx/Rx history can triage cases into likely-benign vs needs-cardiac-workup. `Day1`–`Day5` notebooks + `ethos_omop.py` (extract/load) + `make_demo_extract.py` (synthetic extract, no Snowflake). See `nb/repr_learn_chestpain/README_repr_learn.md`. |
| `nb/repr_learn_letrozole/` | Same 5-day course shape, applied to a letrozole cohort (clustering → sequence mining → PPMI embeddings → surrogate rules validated against the real `death` table). See `nb/repr_learn_letrozole/README_repr_learn.md`. |
| `nb/repr_learn_mammography/` | Pattern discovery on the mammography cohort (`sql/mammography_cohort.sql`): one fused NMF + PrefixSpan notebook asking whether unsupervised structure separates breast-cancer from no-cancer patients. No classifier; filters are listed in the notebook ledger. |

## How to run

### `nb/repr_clmbr/meds_tutorial.ipynb` (no credentials needed)

```bash
pip install -r requirements.txt
pip install meds_testing_helpers
jupyter notebook nb/repr_clmbr/meds_tutorial.ipynb
```
Run from the **repo root** (the notebook resolves data paths relative to it, not to `nb/repr_clmbr/`). Run top to bottom. One cell shells out to `tree` (`brew install tree` on Mac) — skip it if you don't have that installed, it's just a directory listing.

### `nb/repr_clmbr/clmbr_paper_reproduction.ipynb` (needs Snowflake access)

1. Install deps:
   ```bash
   pip install -r requirements.txt
   pip install "meds-etl==0.3.11" meds_reader torch pandas
   ```
2. Set env vars (SSO browser auth is used, so no password needed):
   ```bash
   export SNOWFLAKE_ACCOUNT=...
   export SNOWFLAKE_USER=...
   export SNOWFLAKE_WAREHOUSE=...
   ```
3. Launch Jupyter from the **repo root** (paths like `omop_extract/`, `meds_output/` are root-relative) and run cells **top to bottom** — each stage depends on the previous one's output on disk:
   - **Stage 1** — pull a small patient sample + vocabulary from Snowflake into `omop_extract/*.csv` (ethos_dip disclosure rows are excluded at this step).
   - **Stage 2** — convert `omop_extract/` → `meds_output/` via `meds_etl_omop`.
   - **Stage 3** — convert `meds_output/` → `meds_reader_extract/`.
   - **Stage 4** — build a small code vocabulary using `femr`'s tokenizer stat functions.
   - **Stage 5** — group each patient's events into per-day code sets.
   - **Stage 6** — train the tiny CLMBR-replica model and inspect its learned patient representations.

Re-running Stage 1 re-pulls from Snowflake (new random patient sample unless you fix `person_id`s); everything downstream should be re-run after that.

### `nb/repr_learn_chestpain/` and `nb/repr_learn_letrozole/`

Each is self-contained; see its own `README_repr_learn.md` for setup and the Day1–Day5 run order. How Day 1's bag of codes and NMF are built and validated (labels, prevalence floor, choosing k) is documented in `docs/README.md`. Run from inside the course's own directory (its notebooks resolve `../data_input/`, `../sql/` relative to that directory) — the opposite convention from `nb/repr_clmbr/`.
